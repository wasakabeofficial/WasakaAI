# Session 2026-06-11 — Third Monitor via USB Display Adapter

## Objective
Enable a third monitor on Arch Linux using a MacroSilicon MS9132 USB-HDMI adapter (VID `345f:9132`) that only had Windows driver support.

## Analysis Performed

### Device Identification
- USB device: `345f:9132`, manufacturer "MS", product "USB Video"
- Chip: MacroSilicon MS9132
- 5 USB interfaces: HID, Audio (2x), Vendor Specific, Mass Storage
- USB 3.0 (5 Gbps), serial `77360123`
- The Mass Storage interface is the Windows driver installer partition

### Android APK Reverse Engineering
- Extracted `MSUSBDisplay_Android_V2.0.5.5.apk`
- Found native libraries: `libmsusb.so` (ARM64), `libusb101.so` (libusb wrapper)
- Key symbols: `isms913x`, `s_vid`, `s_pid`, `BULK_WRITE_LEN`, `InitTable`
- Protocol: RGB32 → YUV422 conversion, bulk USB transfers, control transfers for init
- Uses libusb directly (userspace, not kernel driver)

### Driver Research
| Driver | Status |
|--------|--------|
| `yxmicha/ms912x` | ✅ **CHOSEN** — Active, optimized, supports 345f:9132, Wayland-compatible |
| `fathonix/ms9132-drm-linux` | ❌ Official vendor driver, too slow (full framebuffer per frame) |
| `rhgndf/ms912x` | ❌ Reverse-engineered for MS912x (534d:6021), wrong protocol for 9132 |
| Kernel `udl` module | ❌ DisplayLink only (17e9:*), not MacroSilicon |

## Actions Taken

1. **Diagnosed** device via `lsusb`/sysfs — identified as MacroSilicon MS9132
2. **Researched** all existing Linux driver options
3. **Selected** `yxmicha/ms912x` — best driver for our chip
4. **Installed** `linux-headers`, `dkms`, `base-devel`
5. **Cloned** `https://github.com/yxmicha/ms912x` to `~/build/ms912x/`
6. **Compiled** kernel modules from `~/build/ms912x/src/` — both `.ko` files built successfully
7. **Created** installation script `~/build/install-ms912x.sh`
8. **Loaded** modules with `insmod` — third monitor detected and working in KDE Plasma

## Key Decisions
- **ADR-003**: Use `yxmicha/ms912x` over other drivers — correct protocol for 345f:9132, actively maintained, Wayland-compatible
- **No firmware modification** — driver is kernel-only, Windows compatibility preserved
